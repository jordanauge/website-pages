Building and flashing Marlin 2 on a CR-10S V2

2022-07-15 2026-11-02 3D Printing #cr10s #marlin #firmware #platformio #3dprinting
Summary

How to identify your CR-10S mainboard version, pull the right Marlin 2 configuration, build it with PlatformIO CLI, and flash it without the Arduino IDE.

Flashing custom Marlin on a CR-10S is a prerequisite for installing a CR-Touch or any bed levelling probe. The process is not complicated, but it involves identifying your exact board revision, picking the matching configuration, and using PlatformIO to build and upload without the Arduino IDE.

This post is the prerequisite for the CR-Touch installation guide.

Identifying your board version

The CR-10S family spans several mainboard revisions that share the same chassis but differ in firmware requirements. The key distinction is whether your printer has a filament runout sensor — that indicates a V2 or later.

Model Mainboard Filament sensor Notes
CR-10S V1 Creality v2.x (ATmega2560) No Original CR-10S
CR-10S V2 Creality v2.5.2 (ATmega2560) Yes Most common upgraded variant
CR-10S V3 Creality v2.x (ATmega2560) Yes Direct drive extruder
CR-10S Pro 32-bit board Yes Different firmware path entirely

This guide covers V2 with the Creality v2.5.2 ATmega2560 mainboard — the most common variant. V1 and V3 use the same toolchain but require the matching CrealityV1 configuration folder instead.

The board revision is printed on the PCB. You can also verify by looking at the connector layout: the V2 adds a dedicated filament sensor header next to the E motor driver.

Getting the source

Marlin releases two tracks: stable tags and a rolling bugfix-2.0.x branch. For CR-10S work the bugfix branch is recommended — it includes fixes that matter for ABL probes and haven’t reached a stable tag yet.

1
2
git clone --depth=1 -b bugfix-2.0.x https://github.com/MarlinFirmware/Marlin
cd Marlin

Configurations live in a separate repository with a matching branch:

1
git clone --depth=1 -b import-2.0.x https://github.com/MarlinFirmware/Configurations

Copy the CR-10 V2 example config into the Marlin source tree:

1
2
cp Configurations/config/examples/Creality/CR-10\ V2/CrealityV1/Configuration.h    Marlin/Marlin/
cp Configurations/config/examples/Creality/CR-10\ V2/CrealityV1/Configuration_adv.h Marlin/Marlin/

Note: the Configurations repo path is CR-10 V2 / CrealityV1. Despite the name, this folder targets the original Creality ATmega2560 board, not a BTT or MKS replacement. The other subfolders (BigTreeTech SKR 1.4 Turbo, SKR Mini E3 2.0, SKR Pro v1.2) are for aftermarket 32-bit boards.

Required changes to Configuration.h

The bundled example is a reasonable starting point. The following changes are needed before building:

// Uncomment one of these to match your thermistor type.
// Creality stock hot end thermistor is EPCOS 100kΩ NTC = type 1.
#define TEMP_SENSOR_0 1

// Bed thermistor — Creality stock is also type 1.
#define TEMP_SENSOR_BED 1

// Extruder steps/mm — stock CR-10S V2 E-stepper.
// Adjust after an extrusion calibration run.
#define DEFAULT_AXIS_STEPS_PER_UNIT   { 80, 80, 400, 95 }

For BL-Touch / CR-Touch, see the CR-Touch installation guide for the additional defines. Build once without probe support first to confirm the base firmware flashes correctly.

Toolchain: PlatformIO CLI

PlatformIO is the recommended build system for Marlin 2. The Arduino IDE path exists but PlatformIO is faster and produces cleaner output.

Install via pip (or into an existing Python environment):

1
pip install platformio

Identify the correct PlatformIO environment for the ATmega2560 Creality board:

1
grep -r "env:" Marlin/platformio.ini | grep -i "mega\|creality\|2560" | head -10

The target environment is mega2560. Build:

1
2
cd Marlin
pio run -e mega2560

A successful build produces .pio/build/mega2560/firmware.hex.

Flashing

Via USB (avrdude / PlatformIO)

Connect the printer to your computer via USB. The CR-10S exposes a CH340 USB serial adapter; on Linux it appears as /dev/ttyUSB0, on macOS as /dev/tty.usbserial-*.

1
pio run -e mega2560 --target upload

PlatformIO auto-detects the port. If it fails to find the board, specify it:

1
pio run -e mega2560 --target upload --upload-port /dev/ttyUSB0

Via OctoPrint (Firmware Updater plugin)

If OctoPrint is already running and connected, the Firmware Updater plugin can flash the .hex directly without touching the USB cable. In the plugin settings, set the MCU type to ATmega2560 and point it at the .hex from the build output above.

This is convenient if the printer is on a network and you do not want to move the USB cable to a different machine.

First boot verification

After flashing, the printer should boot to the Marlin splash screen and then the main menu. Verify:

  1. Info screen: check that the version string matches the build date (Main menu → About Printer).
  2. EEPROM reset: run M502 (factory defaults) then M500 (save to EEPROM). This clears any stale values from the previous firmware.
  3. Temperature sensors: heat the hot end to 200°C and the bed to 60°C to confirm both thermistors read correctly.
  4. Axis movement: jog each axis from the Move menu to confirm direction and limit switches.

Once the base firmware is verified, proceed with the CR-Touch installation.
