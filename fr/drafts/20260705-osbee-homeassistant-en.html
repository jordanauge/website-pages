OpenSprinkler Bee in Home Assistant — when the app is not enough

2026-07-05 2026-11-02 Home Automation #home-assistant #osbee #opensprinkler #garden #irrigation
Summary

How I went from a cloud-dependent OSBee setup to a local Home Assistant integration and dashboard card that actually fits the Bee hardware.

Introduction

This is the Home Assistant side of a longer garden story. The hardware — pump, tubing, fixed-rate drippers, and why we picked an OpenSprinkler Bee to drive three zones — lives in a companion post on the watering system. Once the Bee was on the network, the real question became: how do I run it from Home Assistant without fighting the wrong abstractions?

Spoiler: I ended up writing an integration and a Lovelace card. Not because I enjoy yak-shaving, but because nothing existing quite matched what the Bee can do and what I wanted from automations.

What I tried first

The vendor app and cloud path

Out of the box, the Bee wants Wi‑Fi setup, then either the local web UI or OpenSprinkler’s cloud (Blynk / OpenThings). The mobile app is fine for a quick manual run. For home automation it is the wrong layer: no device registry in HA, no clean entities, and a dependency on paths I am trying to remove from the garden stack.

Local control works — the firmware exposes a simple HTTP API — but Home Assistant does not ship a first-class OSBee integration.

Existing community projects (and what they are not)

A few projects helped; none was a drop-in answer.

Project What it is good for Why it was not enough for me
hass-osbee YAML switch platforms, uses the PyPI osbee library No config flow, no device page, no services with explicit durations — only switch.turn_on / turn_off
hass-opensprinkler Full OpenSprinkler controllers Different hardware — not the Bee
opensprinkler-card Beautiful dashboard for OpenSprinkler Filters integration: opensprinkler — Bee devices never appear in the card picker; rain delay and water level UI do not apply

Credit where it is due: hass-osbee and the osbee Python package were the starting point for talking to the valves. I did not want to fork them blindly; I wanted config-flow ergonomics, automations, and a dashboard that reflects Bee firmware behaviour (manual runs, quick sequential program, /jc status).

What I actually wanted from Home Assistant

A short wish list — the stuff that sounds obvious until you try to glue YAML switches to real life:

  • One device in the registry with firmware version and a link to the Bee web UI
  • Zone switches whose state follows the valve on the device, not “did I call a service?”
  • Services that accept a zone number and duration — usable from automations without guessing entity IDs
  • Sequential watering using the firmware quick program (pid=81) — potager then flowers, each with its own duration
  • No fake rain delay or water level cluttering the device page (the Bee has neither)
  • A dashboard card that speaks Bee natively, not a trimmed OpenSprinkler clone

That list became the OpenSprinkler Bee integration and the bundled OpenSprinkler Bee Lovelace card.

Install (HACS)

Everything ships from a single public repository — one integration per HACS repo, card bundled inside the integration.

  1. HACS → Integrations → ⋮ → Custom repositories
    Add https://github.com/jordanauge/homeassistant-integrations as category Integration.

  2. HACS → Integrations → search OpenSprinkler Bee → Download.

  3. Restart Home Assistant (or Developer tools → YAML → Reload custom integrations after updates).

  4. Settings → Devices & services → Add integration → OpenSprinkler Bee

  5. Host: local IP of the Bee (shown on the LCD after Wi‑Fi setup)
  6. Token: device key (default opendoor until you change it on the Bee)

  7. Max runtime: upper cap for manual runs (seconds)

  8. Configure the integration → set Default manual run duration (I use 10 s while testing, longer in production).

  9. Dashboard → Add card → search OpenSprinkler Bee (the integration registers the Lovelace resource automatically). Pick any zone switch as the card entity.

If the card does not show up after an update, hard-refresh the browser and check Settings → Dashboards → Resources for /api/osbee/lovelace/osbee-card.js.

Full entity and service reference lives in the repo — README and REFERENCE.md. This post stays at the “why and how to get started” level.

What I can do now

From Home Assistant I can:

  • Toggle Zone 1 / 2 / 3 on the device page or on a dashboard card
  • Run one zone for N seconds via osbee.run_zone in automations
  • Run a sequence (zone 1 for 5 min, zone 2 for 10 min, …) via osbee.run_quick_program or the card’s “Run sequence” button
  • Stop everything with osbee.stop_all or the card’s stop control
  • See live status from the firmware (/jc): active program, time remaining, RSSI

Stored programs and schedules still live on the Bee’s web UI for now — exposing program edit in HA is roadmap, not day-one scope. For summer watering that is fine: automations and the quick program cover 90% of what I need.

Design choices worth naming

Switches vs services — same backend. The switch mirrors valve state from the device; services are for automations and explicit durations. Turning a switch off while a timer runs sends stop immediately — no race with a phantom “60 s left” in software.

opensprinkler-card compatibility — optional shims (entity attributes, legacy service names) exist so you can reuse that card for basic manual runs, but I recommend the OpenSprinkler Bee card: it targets Bee services and drops UI the hardware cannot support.

Placeholder entities (water level, rain delay) stay hidden by default so the device page stays readable; unhide them only if you experiment with opensprinkler-card.
